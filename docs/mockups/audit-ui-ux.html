02

Temuan sistemik

Masalah lintas-halaman, diurutkan dari yang paling menyebabkan rasa “repot”. Lima temuan pertama adalah akar keluhan.

Kritis

Menu menjanjikan fitur yang belum ada

Dari 21 halaman, 6 masih placeholder tetapi tampil aktif di sidebar seakan siap pakai. Pengguna mengklik lalu mentok pada layar “Modul ini masuk tahap pembangunan”. Inilah pemicu utama rasa frustrasi dan kesan sistem “tidak jalan”.

Keuangan DaerahLayanan PublikProfil Data OPDFokus KebijakanDatasetProfil Metadata
Perbaikan: beri badge “Segera”, non-aktifkan klik, atau sembunyikan sampai modul benar-benar siap.
Kritis

Istilah tidak konsisten: sidebar ↔ judul ↔ breadcrumb

Satu hal dipanggil dengan nama berbeda di tiga tempat, sehingga pengguna kehilangan orientasi “saya sedang di mana”.

Sedang

Aksi penyelesaian kurang menonjol

Daftar dan modal detail sudah rapi (stepper 3-tahap bagus), tetapi saat membuka capaian, modal bersifat baca-saja. Tombol untuk benar-benar mengisi / memverifikasi / mengembalikan tidak langsung terlihat. Bagi OPD yang tujuan utamanya mengisi laporan, ini membuat tugas inti terasa berputar.

Perbaikan: jadikan tombol aksi primer menonjol dan menempel (sticky) di dalam modal/halaman detail.
Sedang

Format tanggal campur aduk

Tiga gaya tanggal muncul di halaman berbeda, menurunkan kesan kematangan sistem.

Perbaikan: satu format tanggal konsisten di seluruh aplikasi (mis. 8 Okt 2026).
Sedang

Sidebar terlalu panjang untuk tiap peran

Sekitar 20 item dalam 6 grup. Pengguna OPD yang hanya memerlukan 3–4 menu tetap melihat seluruh daftar, sehingga navigasi terasa membebani. Menu sudah berbasis peran, tapi perlu dipangkas lebih tegas per peran.

Perbaikan: tampilkan hanya menu relevan per peran (OPD ≠ Pimpinan ≠ Admin); satukan sub-item di bawah induk yang bisa diciutkan.
Terpuji

Yang sudah sangat baik — pertahankan

Empty-state konsisten dan informatif, guardrail “hanya data resmi” pada Asisten AI, stepper alur kerja (Diisi → Diperiksa → Disetujui), tabel responsif yang berubah jadi kartu di mobile, dan palet warna yang tenang serta pantas untuk konteks pemerintahan.

06

Prioritas perbaikan

Quick wins

Dampak besar · usaha kecil · bisa pekan ini
  1. Badge “Segera” + non-aktifkan klik untuk 6 modul placeholder
  2. Seragamkan format tanggal di seluruh aplikasi
  3. Samakan nama menu ↔ judul ↔ breadcrumb
  4. Tonjolkan tombol aksi primer di modal detail
  5. Perbaiki overflow filter tab di mobile

Pekerjaan sedang–besar

Dampak tinggi · perlu perencanaan
  1. Tanam grafik tren + peta kecamatan ke Dashboard Pimpinan
  2. Pangkas sidebar per peran (OPD / Pimpinan / Admin)
  3. Tambah panduan “langkah berikutnya” di Beranda Tugas
  4. Sederhanakan Matriks Indikator (mode ringkas + filter ciut)
Catatan Strategi Produk

Rilis lantainya, tahan atapnya

Agar sistem inti matang untuk akuisisi, sekaligus menyisakan fitur andalan sebagai nilai jual berulang ke daerah lain.

Rilis penuh — standar

Fondasi yang meyakinkan calon pengakuisisi.

  • Administrasi (user, role, organisasi)
  • Pelaporan → Verifikasi → Publikasi
  • Matriks Indikator
Tahan — modul ekspansi

Biarkan sebagai “Segera”; bisa jadi paket terpisah per daerah.

  • Keuangan Daerah
  • Layanan Publik
Moat — hanya kamu

Rilis tampilannya, pegang otaknya sebagai IP/lisensi.

  • Asisten AI + Analisis Keputusan (mesin rekomendasi & sinyal prioritas)
  • Engine geo-analitik antar-kecamatan

Catatan: perjelas kepemilikan IP di perjanjian dengan pihak pengakuisisi — pisahkan “sistem inti” (boleh diakuisisi) dari “engine andalan” (tetap milikmu, berbasis lisensi). Ini ranah hukum/bisnis; strukturnya layak disiapkan sejak awal.
